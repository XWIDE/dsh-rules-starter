# 防修坏护栏（给本地模型的手铐）

> **为什么需要它**：不是它笨 —— 是「能改真实文件」这件事本身太危险。宿主已经因为文件被改坏、起不来过好几次，其中**有几次是 Agent 自己改的**（见你自己的规则本）。教它方法（文档）只是第一层；真正管用的是**让它在物理上改不坏**。
> 路径占位符：`<HOME>`＝你的用户目录，`<修复目录>`＝你放修复脚本的那个目录。

---

## 四层护栏（从软到硬，缺一层就漏一层）

| 层 | 是什么 | 状态 | 作用 |
|---|---|---|---|
| 1 **文档层** | 规则本顶部「🧭 东西坏了？先读方法卡」＋ [排障方法卡.md](排障方法卡.md) | ✅ 已接 | 给它方法：先 grep 报错到源码行 → 读懂判据 → **拿到判定器** → 好样本对照 → 副本上改+验证才写回。**不保证它执行。** |
| 2 **权限层（最硬）** | 文件策略保持 **workspace-write**（默认值） | ✅ 默认已生效 | 写工作区外的路径会被 **`EPERM: operation not permitted`** 直接拒绝。实测：改 `<HOME>\.dsh\sessions\` 被拦下，**必须显式提权**才放行。 |
| 3 **动作层** | 任何写真实文件的动作**一律走脚本**（`safe_write.mjs` 这类） | ✅ 已备并自测 | 备份 → 覆盖 → **复读校验哈希** → 任一步失败**自动回滚**。手写 `Set-Content` / `Copy-Item` 直接覆盖真实文件 = 违规动作。 |
| 4 **恢复层（兜底）** | 桌面一键急救脚本：只读体检 · 看历史版本 · 回滚 · 隔离插件 · 撤销上一次 | ✅ 已有 | 真改坏了也回得来。**先备份再动手 = 永远留退路。** |

### 🔴 权限层红线（最容易被"好心"破坏的一层）

**永远不要给它 `danger-full-access` ＋ `approval: never`。**
这两个一起开 = 它可以**静默**改真实会话日志 / 插件 / 核心配置，出错时**没有任何提示、没有人拦**。
需要它动真实目录时：**只放行那一条命令**（一次性提权），不要改全局策略。
（本会话的运行时策略曾一度被切到这种组合 —— 那种状态下第 2、3 层等于不存在。）

---

## 给本地模型的三条硬规矩（贴进它的会话开头也行）

1. **只改副本**：要动真实文件，**先复制到 `<修复目录>\` 改**，改好再走安全写回脚本。
2. **没有判定器不改**：先跑官方校验（全量体检脚本或官方读取入口），拿到 OK/FAIL 再动手。**没有尺子不许下刀。**
3. **报错换位置 = 没修好**：第二次失败就**停手报「我卡在哪」**，禁止再换方向试（这就是它上次改 N 次没好的原因）。

## 自测记录（安全写回脚本，五例全部实测）

| 用例 | 结果 |
|---|---|
| ① 正常写入 | `OK wrote …` + 备份落盘（1 个）+ **复读内容 = 新内容** |
| ② 源文件不存在 | `FAIL 源文件不存在` —— **目标内容原样未动** |
| ③ 目标目录不存在 | `FAIL 目标目录不存在` —— `dir_created=False`（不凭空造目录） |
| ④ 源是目录（非法） | `FAIL 源不是普通文件` —— 干净报错，**目标未动** |
| ⑤ **故障注入 → 回滚** | `ROLLED BACK … 已恢复写入前字节` —— 回滚后哈希**等于写入前哈希**（`rollback_ok=True`） |

**⚠️ 自测踩坑（第一次自测是无效的，已作废重做）**：用宿主 exe 以 `ELECTRON_RUN_AS_NODE` 跑脚本时，**PowerShell 不会等待这个 GUI 程序结束**，脚本还在写、`Get-Content` 已经读完了 —— 会读到**旧内容**并误判"没写进去"。正确姿势：**跑完加 `Start-Sleep -Seconds 3`（或 `Start-Process -Wait`）再看结果**；更稳的是让脚本自己 `writeFileSync` 落一份结果文件，你再去读那个文件。
