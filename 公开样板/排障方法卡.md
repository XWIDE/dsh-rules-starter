# 排障方法卡（给本地模型的自用规程）

> 适用：**"东西坏了，但不知道坏在哪"** 这一类活 —— 会话打不开、文件报 corrupt、插件写了不生效、启动崩溃、数据不对。
> 本卡只讲**方法**（怎么想、按什么顺序做、怎么证明做对了）。具体案例见你自己的工具箱笔记。
> 路径一律写成占位符：`<安装目录>`＝宿主装在哪填哪，`<HOME>`＝你的用户目录。

---

## 0. 一句话总纲

**先造尺子，再下刀；没有尺子的改动，一律不算"修好"。**

尺子 = **判定器**：一段能对「坏文件 / 改后的文件」明确说 OK 或 FAIL 的**官方代码**。有了它，你对错就不用靠猜，也不用靠嘴。

---

## 1. 五步固定动作（照顺序走，别跳步）

| 步 | 动作 | 产出（必须写出来） |
|---|---|---|
| 1 | **把报错原文当线索，grep 到源码行** | 一句「哪一行代码判我坏」+ `文件:行号` |
| 2 | **读懂那条判据**（读它上下 20–40 行状态机） | 一句人话（例：「turn 号必须等于 nextTurn」） |
| 3 | **拿到判定器**：把官方校验逻辑**离线跑起来** | 能对任意文件输出 OK/FAIL 的脚本 |
| 4 | **找一个好样本对照**：同类正常文件解出来，跟坏文件逐条并列比 | 差异清单（通常只有 1–2 处） |
| 5 | **副本上改 → 判定器 OK → 内容核对 → 才写回原文件** | 备份路径 + 写回后复验结果 |

**第 1 步的细节**：grep 报错时**不要 grep 整句**，挑最独特的 3–6 个词（例：`does not open the expected turn`）。宿主自己的代码在 `<安装目录>\resources\app\node_modules\`。

**第 3 步的细节**：优先 `import` 官方模块跑官方逻辑；实在进不去，就把判据**照抄成 20 行脚本**，并在结论里标明「这是照抄的判据，不是官方入口」。

**第 4 步为什么值钱**：读文档、读注释都要靠理解；**对照好样本只需要"哪里不一样"**。好样本怎么找：同目录、同类前缀、最近写成功的那些文件。

---

## 2. 三条禁令（就是"改了好几回还是没好"的原因）

1. **禁止"换位置撞同一堵墙"。**
   报错从 A 点挪到 B 点 = **没修好**，是同一个根因换了个出口。
   ⇒ 一旦第二次失败，**回头重读第 2 步的判据**，不要再往同一方向试（`①不许死循环`）。
   *真实教训*：上一版只把冲突从 `seq=4` 挪到了 `seq=11`，两次报错原文不同、根因是同一个（时序/编号不匹配）。

2. **禁止"改完不做判定"。**
   `try/catch` 吞掉、日志没报错、界面看起来正常 —— 都**不算**。判定器说 OK 才算。
   *真实教训*：坏文件在**写入时**一切正常、只有**读取时**才炸；"写的时候没报错"根本不构成证据。

3. **禁止"只修一处就收工"。**
   同一类错误通常成批出现。修完一处 → **先全量扫同类并分类（flavor）** → 再逐个修。
   *真实教训*：一百多个文件里九成好、一成坏、还分好几种坏法；只修用户报的那一个，剩下几个照样打不开。

## 3. 五个最容易把人带偏的误判（省时间用）

1. **"文件损坏" ≠ 文件字节坏了。** 先分层判断：字节层（能不能解压/能不能 parse）→ 结构层（事件类型/字段）→ **语义层（事件之间的关系）**。本例字节层全好、JSON 全可解析，坏在语义层。
2. **别靠"搜魔数"找压缩帧边界**：zstd 的 payload 里 `28 b5 2f fd` 会大量误命中。按 block header 逐帧推算。
3. **要插入/删除记录前，先查"格式是否要求稠密"**。本例 `seq` 必须连续 ⇒ 插一行就要**重排全部 seq + 重映射全部引用字段**。
4. **官方模块 import 失败时，先看它为什么炸**，不要放弃判定器。本例：构造要真 `cordis.Context`，手写 stub 会 `Cannot read properties of undefined (reading 'provide')`。
5. **判定器有"身份/路径检查"时，别为了讨好它去动真实文件** —— 造一个**假目录结构**（假 root）就能离线验证真文件。

## 4. 命令模板（照抄可用；工作区已有现成脚本别重写）

```js
// ① 逐帧解 zstd（Node 用宿主自带的 Electron：$env:ELECTRON_RUN_AS_NODE=1; & "<宿主 exe>" x.cjs）
//    坑：zstdDecompressSync(整文件) 只解第一帧；流式拼接会报 Unknown frame descriptor
//    正确：按 block header 扫帧边界 → 逐帧 zstdDecompressSync → 拼明文

// ② 判定器：**一条命令版（已封好 —— 用这个，别自己搭）**
//    node <修复目录>\verify_session.mjs "<会话日志路径>"          # 判一个（也可一次给多个）
//    node <修复目录>\verify_session.mjs --all "<会话目录>"        # 全量体检
//    它自动把文件暂存到工作区的假 root 再调官方读取链 → 不动原文件、不碰真实会话目录
//    （跑完记得 Start-Sleep 再读输出 —— 宿主的 exe 是 GUI 程序，PowerShell 不等它）
// 下面是它的内部原理（要自己给别的格式搭判定器时照这个写）：
//   Node 里 import 官方模块要用 file 协议的 URL：把下面的反斜杠换成斜杠，并在最前面补上「file 协议前缀＋两个斜杠」。
import JsonlSessionPersistence from "<安装目录>/resources/app/node_modules/@deepseek-ai/dsh-session-persistence-jsonl/lib/index.js";
import * as cordis from "<安装目录>/resources/app/node_modules/@deepseek-ai/cordis/lib/index.js";
const p = new JsonlSessionPersistence(new cordis.Context(), { root: FAKE_ROOT, compression: "zstd" });
await p.readStoredLog(path, id);      // 抛错 = 坏；返回 events = 好
// FAKE_ROOT 里要摆出"官方会去找的那个路径"：<FAKE_ROOT>\<工作区路径转义>\<session-id>\session.v4.jsonl.zstd

// ③ 内容指纹核对（防"修好了但丢数据"）
//    对 message 事件取 role+content 的哈希做成 multiset，改前改后比：missing 必须为空
```

现成脚本该有哪几个（名字随你起，职责别少）：

| 脚本 | 干什么 |
|---|---|
| `scanall` | 用官方判定器全量体检（一百多个会话 ≈20 秒） |
| `fix_and_verify` | flavor 1（编号重复）修复 + 验证 |
| `repair2` | flavor 2/3（缺 turn/step、缺 surface 头）插行 + 重排 seq/引用 + 验证 |
| `apply_fix` | 备份 → 写回真文件 → 复读复验 |
| `check_content` | 内容指纹比对（missing/extra） |

## 5. 交活自检（每条都要贴证据，贴不出 = 没做）

- [ ] 判定器输出的**原文一行**（改前 FAIL、改后 OK）
- [ ] 内容核对结果（`missing=NONE`）
- [ ] 备份路径 + 哈希（改前改后）
- [ ] 全量扫描的**前后数字**（例：9 FAIL → 0 FAIL / 157 OK）
- [ ] 如实写清「**没验证什么**」（例：没点过 UI、没实测追加写入）

---

## 6. 最后一句

**上次不是不聪明，是手里没有尺子。**
造尺子（判定器）→ 量（好样本对照）→ 剪（**只在副本上**改）→ 复量（写回后再验一次）。
这四步走完，改几次都不会"越改越坏"。
